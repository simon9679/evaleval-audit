# Public claim register before testing

Status: frozen scope, not results.

## C1 - Four-signal layer
Evaluation Cards publicly presents four interpretive signals: reproducibility, completeness, provenance, and comparability.

## C2 - Reproducibility construct
Public wording asks whether another party can run the evaluation under the recorded setup and obtain the same result or number. The audit must test the operationalization actually implemented, not the natural-language label alone.

## C3 - Completeness construct
Public wording presents completeness as whether benchmark documentation is sufficient to interpret a score. The audit must identify the actual field set and aggregation rule before judging this claim.

## C4 - Provenance construct
Public wording presents provenance as who reported a score and whether it has reproduction or corroboration across sources. The audit must distinguish source multiplicity from independent accuracy.

## C5 - Comparability construct
Public wording presents comparability as whether reported scores correspond to the same measurement target under sufficiently comparable setups. The audit must test both discrimination of relevant setup changes and invariance to irrelevant changes.

## C6 - Canonical-record composition
Evaluation Cards publicly states that it composes run data, benchmark metadata, and model metadata into a canonical record. This supports later lineage and provenance tests.

## C7 - Corpus-level descriptive claims
Published percentages and counts are snapshot-specific. A dated launch claim and the current live site may legitimately differ. Any audit comparison must bind each number to its stated snapshot.

## C8 - Broad corpus-superlative claims
Statements such as largest or most comprehensive corpus require comparison against external alternatives. They are not included in the first confirmatory test and must not be silently treated as validated by internal pipeline checks.
